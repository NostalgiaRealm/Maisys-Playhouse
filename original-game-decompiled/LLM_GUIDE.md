# LLM guide: original-game-decompiled

Read `README.md` first. This file tells an agent how to answer questions from this package without redoing the analysis.

## Ground rules

- Evidence is static. Nothing here was observed running. Keep "confirmed in code/data", "inferred" and "unresolved" apart when you quote from it.
- Pseudocode in `decompiled/**` is generated by Ghidra. `FUN_`, `DAT_`, `param_`, `local_` names are placeholders. Library names (`__beginthreadex`, `AfxTryCleanup`...) come from Ghidra's signature matching and can be wrong in detail.
- One-byte functions named `__break` are int3 padding, not code. Skip them (5,818 in Maisy.exe, 543 in NETWORK.R32).
- Entries from `recovered_functions.tsv` with method `clean-gap-fragment` or `orphan-instructions` may be SEH funclets, switch-case blocks or incremental-link jump thunks rather than whole functions.
- Maisy.exe was linked incrementally: most calls go through `jmp` thunks near the start of `.text` (`thunk_FUN_...`, 0x00401000-0x00402FFF). Follow the thunk to the real body.

## Architecture in one page

```
Autorun.EXE (Wise)  ->  Install.exe (Wise)  ->  shortcut: Maisy.exe "Data.mfx"   [not gameplay]

Maisy.exe = mTropolis 2.0 player (MFC app, MSVC, 32-bit)
  loads  mPlugins\*.x32/.r32/.c32  via LoadLibraryA + GetProcAddress(ordinal)   (0x00435A30)
  opens  data.mfx  (catalog, boot stream, scene structure, modifiers, Miniscript bytecode)
  opens  data2.mxx (segment 2: media) from the CD
  draws  into DIB sections, BitBlt to its window; palettes on 8-bit displays
  plays  PCM through waveOut; mmio for files; MCI present for MIDI/AVI paths
```

The game logic is *data*: scenes, elements, modifiers and Miniscript in `data.mfx`/`data2.mxx`, interpreted by Maisy.exe and the plug-ins. There is no Maisy-specific native code in any module: the executables are stock mTropolis runtime. To learn what an activity does, read `authored-content/`; to learn how a modifier type behaves, read the plug-in export of the same name.

## Mapping authored content to native code

- Built-in object types (elements, behaviors, messengers handled by the player) are parsed and executed inside Maisy.exe.
- A plug-in modifier in the data carries its type name as a string; the player resolves it to the export with the same name in one of the loaded plug-ins (`decompiled/plugin__*/exports.csv`). Example: a `miniscriptmod` object -> `BASIC.X32!miniscriptmod` (0x11004010); `hlPrintBitmap` -> `Bitmap.r32!hlPrintBitmap` (0x10003540).
- Every plug-in export is a single dispatcher `uint __cdecl f(Block*)` keyed by a selector at `Block+4` (see `annotations/key_functions.md`).
